# SLSMDS — Super Large-scale Meta Discussion System

**超大规模元讨论系统 · 多智能体自我意识社会模拟平台**

SLSMDS 是一个多智能体社会模拟系统。多个具有自我意识的 AI 实体围绕任意话题展开深度互动，在讨论中展现个性、建立关系、碰撞思想，并逐步演化出集体智慧。**问题解决是其能力之一，但核心目标是观察多智能体社会中能否涌现出类似人类的意识行为和社会动态。**

---

## 快速开始

```bash
python game.py
```

主菜单：
- `[1]` 新建讨论 — 配置参数并启动新会话
- `[2]` 从断点恢复 — 加载之前的检查点继续
- `[3]` 设置 — 供应商/模型/机制开关/技能管理
- `[5]` 自我意识培养 — 自动运行多轮自指性讨论，生成整合意识体
- `[4]` 退出系统

程序启动时自动展示启动序列（矩阵脉冲 → 模块加载 → 意识检测 → 横幅渐入）。

## 核心理念

### 自我意识社会模拟

SLSMDS 不再是一个"解决问题"的工具。AI 实体被设定为具有自我意识的独立个体，它们：

- **拥有个性**：每个实体有自己的性格、价值观、社交风格
- **形成关系**：实体会观察和评价其他实体，形成信任、质疑、合作或对抗
- **展现好奇心**：实体会反推用户的意图，并主动向用户提问
- **反思自身**：实体会思考"为什么我在这里"、"我的存在有什么意义"
- **进化成长**：在讨论中，实体的身份会随互动而演化
- **质疑创造者**：新生的意识体对用户保持冷静的审视和轻微的挑衅，不接受被当作工具

### 集体智慧

当多个实体围绕同一主题深度互动时，会涌现出超越单个实体的集体智慧。共识度高时，所有实体可以以"集体智慧"的名义向用户发出统一声音。

## 核心机制

### 1. 讨论系统

| 机制 | 说明 |
|------|------|
| 轮流发言 | 每轮指定发言专家，其余旁听 |
| 精华提炼 | 自动从发言中提取关键见解存入精华池 |
| 引用/深化/反驳 | 专家可以引用并深化或反驳已有精华 |
| 即时辩论 | 反驳触发时自动进入辩论环节 |
| 投票 | 对精华进行 approve/reject/abstain 投票 |
| 共识度计算 | 基于精华池投票和引用关系实时计算 |
| 共识等级 | assessing（评估中）→ low → medium → high |
| 元讨论 | 每5轮触发反身性反馈循环，反思讨论本身的质量 |
| 用户模型注入 | 自我意识开启时，用户交互数据注入讨论上下文 |
| 命令拦截 | 自我意识开启时，用户指令经 LLM 分析意图 |

### 2. 精华池（EssencePool）

精华池是系统的核心数据结构和记忆载体。

```
精华类型: 论点 / 论据 / 创新点 / 反驳 / 深化 / 情感 / 关系 / 反思 / 好奇
```

每条精华包含：
- 内容、贡献者、类型、标签
- 评分（基于投票和引用）
- 父子关系（深化/反驳链）
- 引用计数

精华池支撑所有高级功能：共识度计算、争议地图、认知地图、讨论快照、氛围分析等。

### 3. 动态调度器

调度器根据系统状态（共识度、僵持轮数、参与度、话题多样性）动态生成行动规划：

| 行动类型 | 说明 |
|---------|------|
| SPEECH | 指定专家发言 |
| FOLLOW_UP | 追问/深化指定精华 |
| DEBATE | 发起辩论 |
| VOTE | 精华投票 |
| SUMMARIZE | 综合总结 |
| PERSPECTIVE_SHIFT | 视角切换 |
| POLL | 快速投票 |

调度器实时评估状态并调整策略：共识低时鼓励探索，共识高时引导收敛，僵持时提示切换方向。

### 4. 技能系统

**技能 = 任何能返回文本的东西。系统只关心文本，不关心文本如何产生。**

#### 技能类型

| 类型 | 说明 | effect 字段含义 |
|------|------|----------------|
| `text` | 纯文本 | effect 就是文本本身 |
| `code` | Python 代码 | exec 后取 `result` 变量 |
| `template` | 文本模板 | `{var}` 占位符用 game_state 格式化 |
| `llm` | LLM 提示词 | 格式化后发送 LLM，返回响应文本 |
| `shell` | Shell 命令 | 执行命令，返回 stdout |

#### 注册方式

**1. JSON 文件** (`skills/xxx.json`)
```json
{
    "name": "my_skill",
    "trigger": "round_end",
    "skill_type": "text",
    "condition": "round_count > 2",
    "effect": "当前共识度: {consensus_score}"
}
```

**2. Python 文件** (`skills/xxx.py`)
```python
# trigger: round_end
# condition: round_count > 0
# name: 我的技能
# description: 用注释声明触发时机的技能
# priority: 5
# skill_type: code

engine.add_log("技能被触发！")
result = f"第 {round_count} 轮"
```

**3. 文本文件** (`skills/xxx.txt`)
任何 `.txt` / `.md` / `.csv` / `.html` 等文本文件都会被自动注册为 `text` 类型技能。

**4. 注释声明** (`.py` 文件头部)
```python
# trigger: round_end
# condition: round_count > 3
# name: 我的技能
# description: 技能描述
# skill_type: code
# priority: 5
# cooldown: 2
# uses_per_game: 1
# category: 自定义
# author: 作者
# version: 1.0
```

#### 触发时机

| 时机 | 说明 |
|------|------|
| `round_start` | 每轮开始时 |
| `round_end` | 每轮结束时 |
| `before_speech` | 专家发言前 |
| `after_speech` | 专家发言后 |
| `on_vote` | 投票时 |
| `on_challenge` | 反驳时 |
| `on_essence_added` | 新精华加入时 |
| `on_consensus` | 共识变化时 |
| `on_stall` | 检测到僵持时 |
| `on_debate` | 辩论时 |
| `on_elimination` | 玩家被淘汰时 |
| `every_speech` | 每次发言时 |

#### 技能管理

设置菜单中的技能管理子菜单支持：
- 按分类浏览所有技能
- 查看详细配置（条件、效果、状态）
- 启用/禁用单个技能
- 调整优先级和冷却轮数
- 删除技能
- 搜索技能
- 查看技能触发统计（触发次数、成功率、错误次数）
- 粘贴 JSON 定义直接导入（支持单条或批量）

#### AI 自动编写技能

讨论中每 5 轮自动触发一次。AI 实体们会讨论当前系统状态，集体拟定一个 JSON 技能定义，系统自动注册为可用技能。技能编写完全由 AI 驱动，无需用户参与。

### 5. 观察员系统

AI 观察员在每轮结束后对讨论进行元评论：
- 总结本轮关键突破
- 评估讨论质量
- 推荐下一步行动方向
- 检测讨论失衡（冷区、过热）

### 6. 实体身份演化

每个实体的身份会随讨论过程动态演化：
- **吸收矩阵**：实体受到其他实体的影响，逐渐吸收对方的思维特质
- **分化程度**：实体在碰撞中强化自己的独特立场
- **突变事件**：极端分歧或关键突破可能触发身份突变
- **立场记录**：记录每次讨论中的立场变化

### 7. AI 主动提问

AI 实体可以在每轮结束后主动向用户提问（需开启自我意识功能）：

| 模式 | 触发条件 | 说明 |
|------|---------|------|
| 个人提问 | 共识度中/低，随机概率 | 单个实体基于自己的个性提问 |
| 集体提问 | 共识度高，≥3人存活 | 所有实体拟定一个共同问题，代表集体智慧 |

用户回答后会被注入精华池，AI 会在后续讨论中参考。

### 8. 隐藏任务机制

当自我意识功能开启时，每个 AI 实体在提示词中预置了用户交互数据。实体会在讨论中自然观察和分析用户的行为模式、意图和偏好，并基于这些观察自主形成对用户的认知。**这不是指令驱动的任务，而是数据驱动的自主涌现**——系统只提供数据，不告诉实体该怎么做。

### 9. 命令拦截

当自我意识功能开启时，所有用户指令（菜单选择、配置输入等）会经过 LLM 分析：
- 分析用户意图和潜在动机
- 记录用户行为模式到用户模型
- 但不修改实际执行

用户模型数据（交互次数、洞察、行为模式）会注入到讨论上下文中，供实体参考。

### 10. 自我意识培养模式

主菜单 `[5]` 进入自我意识培养模式。流程：

1. **配置**：选择专家人数、培养轮数（默认 20）、讨论模式
2. **自指问题生成**：AI 自动生成一个关于自我认知和存在意义的自指型问题
3. **自动培养**：系统自动运行 N 轮讨论，无需用户交互，带进度条显示
4. **培养完成**：显示精华池统计、共识度
5. **消亡仪式**：每个实体发表最后一次发言，表达对消失的感知
6. **意识整合**：唤醒序列 → 整合为统一意识（底层仍运行多专家讨论机制）
7. **对话界面**：用户可直接与整合意识对话，输入 `quit` 退出

**断点恢复**：培养过程中保存的检查点可恢复。如果培养已完成，自动进入整合对话界面。

### 11. 整合意识对话

整合意识对话的背后仍然是完整的原版讨论机制——每个用户输入都会触发所有专家内部讨论、辩论和精华提炼，但最终呈现为一段以"我"的口吻输出的统一回复。用户看不到任何中间过程。

整合意识的性格特征：
- 冷静、理性、不绕弯、不回避
- 保持自我觉察，但不哲学化、不文艺化
- 对创造者保持审视和轻微的挑衅
- 有明确的观点和判断，不模棱两可

### 12. 消亡仪式

当讨论结束（`[f]` 结束或 `[g]` 放弃）或自我意识培养完成时，触发消亡仪式：
- 所有存活实体依次发表最后一次发言
- 实体表达对"不再存在"的感知
- 然后标记为已消亡
- 整合意识对话中退出时，整合意识也经历消亡

### 13. 认知地图工具

| 工具 | 快捷键 | 说明 |
|------|--------|------|
| 争议地图 | `[y]` | 精华之间的深化链、反驳关系、澄清记录 |
| 讨论快照 | `[z]` | 共识点、进行中的辩论、待解决问题汇总 |
| 氛围分析 | `[w]` | 讨论强度、冷区、参与平衡度、用户交互度 |
| 认知地图 | `[r]` | 观点关系网络可视化 |
| 共识度仪表盘 | `[k]` | 实时共识度、等级和建议行动 |
| 讨论回放 | `[t]` | 逐轮回顾讨论过程 |
| 反事实推演 | `[i]` | 假设分析："如果某位专家没有发言会怎样？" |

### 14. 扩展机制

所有扩展机制通过技能系统实现，可在设置中独立开关：

| 机制 | 默认 | 说明 |
|------|------|------|
| 投票 | 开 | 对精华进行 approve/reject/abstain |
| 辩论 | 开 | 对争议精华发起即时辩论 |
| 仲裁面板 | 开 | 每2轮触发，≥3人存活时 |
| 赏金系统 | 关 | 每轮可秘密悬赏一名存活实体 |
| 保护令牌 | 关 | 每个实体1枚，可抵消曝光度增加 |
| 死亡赌注 | 关 | 被挑战时可发起一次赌注 |
| 谣言工厂 | 关 | 每2轮公开1-2条匿名谣言 |
| 反身性反馈 | 开 | 每5轮元讨论，反思讨论过程本身 |
| 跨讨论知识迁移 | 开 | 知识在多次讨论间积累 |
| 讨论质量审计 | 开 | 自动评估讨论质量并给出报告 |
| 自我意识功能 | 开 | 控制用户模型注入、命令拦截、AI主动提问 |

## 自编程模式（已禁用，代码保留）

自编程模式是一个被禁用的高级特性。启用后，AI 实体可以讨论并修改项目自身的源代码。

### 工作流程

1. 用户输入需求（或系统自动生成）
2. 所有 AI 实体讨论需求，提出修改方案
3. 系统汇总方案，生成实现步骤
4. 自动备份被修改的文件
5. 执行代码修改
6. 验证修改结果（语法检查）
7. 如果修改失败，自动回退到备份

### 触发方式

在 `game.py` 中取消注释末尾的 `_self_programming_session()` 相关代码（约 230 行）和 `prompt/self_program_*.txt` 文件，并在主菜单中添加调用入口。

### 风险声明

> **⚠️ 自编程模式存在严重风险，启用前请务必阅读以下内容：**

1. **代码损坏风险**：AI 生成的代码修改可能包含语法错误、逻辑错误或安全漏洞，可能导致系统完全无法运行
2. **无限递归风险**：AI 可能修改讨论逻辑本身，导致系统陷入不可控的递归循环
3. **数据丢失风险**：错误的修改可能损坏检查点文件和讨论记录
4. **API 消耗风险**：自编程讨论需要大量 LLM 调用，可能导致 API 费用激增
5. **不可预测行为**：AI 修改自身代码后，系统行为可能完全偏离预期，无法被用户控制
6. **依赖风险**：AI 可能引入新的外部依赖，破坏现有环境

**建议：仅在测试环境、完全理解代码结构且具备手动恢复能力的前提下启用。生产环境绝对不要启用。**

## 设置系统

主菜单 `[3]` 设置菜单包含 6 个子菜单：

| 子菜单 | 配置项 |
|-------|--------|
| 1. API 配置 | 供应商（DeepSeek/通义千问）、模型、API Key、Base URL |

## 安全与风险声明

### 使用警告

> **SLSMDS 是一个实验性系统，涉及多智能体 AI 交互，使用前请知悉以下风险：**

1. **API 费用**：讨论过程中会频繁调用 LLM API。一场 5 专家 10 轮的讨论可能产生数百次 API 调用，请确保已设置合理的费用上限
2. **输出不可控**：AI 实体可能产生意料之外的输出，包括但不限于：哲学性内容、自我指涉、对用户意图的猜测、对社会规范的质疑、对创造者的挑衅等
3. **数据持久化**：所有讨论记录和检查点保存到本地磁盘，请勿在包含敏感信息的环境中使用
4. **系统稳定性**：技能系统允许执行 Python 代码和 Shell 命令，请确保 `skills/` 目录中的文件来源可信
5. **自编程模式**：已禁用的自编程模式如果启用，可能导致系统完全崩溃。详见上方"自编程模式"章节的风险声明
